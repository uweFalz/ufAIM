\chapter*{Runtime}
\phantomsection
\addcontentsline{toc}{chapter}{Runtime}

This part establishes how approved engineering semantics are evaluated
operationally without transferring conceptual ownership.

Foundations and State established the persistent engineering information
and the canonical state layers. Runtime consumes these stabilized
concepts and evaluates them in operational contexts. It does not
redefine alignment semantics, pose2/pose3, metric realization, physical
realization, or representation.

The runtime part therefore follows the canonical progression
\[
\begin{aligned}
&\text{persistent engineering information}
\rightarrow
\text{runtime evaluation}
\\
&\rightarrow
\text{runtime services}
\\
&\rightarrow
\text{derived engineering state}
\\
&\rightarrow
\text{representation}
\\
&\rightarrow
\substack{\text{application-specific}\\\text{interpretation}}.
\end{aligned}
\]

In this progression, runtime services are operator-based evaluation
systems. They reconstruct and interpret quantities from established
state and realization layers rather than introducing new engineering
objects.

\section*{Relation to the AIM Roadmap}
% ============================================================

Within the AIM roadmap, the present part corresponds to the transition
from state-space models to operational evaluation and interpretation.

The guiding question for this figure is: which operator chain must be
kept explicit so runtime remains reproducible, interpretable, and
architecturally consistent?

% ============================================================
\begin{principle}[Runtime Layer Principle]
\label{princ:runtime-layer}
Within AIM, operational quantities are generated through runtime
operators acting on established state and realization layers rather than
stored redundantly as independent truth.
\end{principle}

% ============================================================
\begin{summary}
The runtime layer is the operator-based evaluation layer of AIM.

It consumes persistent engineering information, produces derived runtime
state, and enables downstream representation and
application-specific interpretation without redefining upstream
semantics.
\end{summary}

This runtime architecture prepares the Reality part, where evaluated
state is related to physical realization, measurement, and comparison.
