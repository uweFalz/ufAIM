\chapter*{Runtime and Evaluation}
\addcontentsline{toc}{chapter}{Runtime and Evaluation}

\begin{remark}
Classical railway alignment theory primarily focuses on static geometry.
\end{remark}

\begin{remark}
Within AIM, however, alignments are not interpreted as passive curves,
but as continuously evaluated runtime structures.
\end{remark}

\begin{remark}
Projection, frame construction, realization evaluation, dynamic
interpretation, and optimization are therefore treated as runtime
processes operating on alignment states.
\end{remark}

\begin{remark}
This part introduces the computational and conceptual runtime layer that
connects:
\begin{itemize}
\item intrinsic geometry,
\item world-space interaction,
\item realization-aware modelling,
\item runtime projection,
\item and operational evaluation.
\end{itemize}
\end{remark}

\begin{remark}
Within AIM, runtime is not merely software execution.
It denotes the dynamic evaluation layer between mathematical alignment
models and physically interpreted railway states.
\end{remark}
