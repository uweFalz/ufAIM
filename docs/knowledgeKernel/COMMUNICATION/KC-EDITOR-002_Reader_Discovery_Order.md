# KC-EDITOR-002 Reader Discovery Order

## Status
candidate

## Canonical Question
In which order should readers encounter Kernel concepts in explanatory material?

## Candidate Canonical Answer
Reader discovery order is an explanatory dependency order: prerequisite concepts are introduced before dependent concepts. This order may differ from Research chronology and implementation sequence, and it remains subordinate to Kernel meaning and Governance authority.

## Normative Meaning
- Reader order is determined by conceptual dependency, not by historical discovery date.
- Reader order may differ from implementation build order or software composition order.
- Editorial sequence cannot define engineering identity, architecture, or concept ownership.
- Prerequisites are introduced first so dependent concepts are interpretable and testable.
- Editorial sequencing serves understanding and traceability; it does not change canonical semantics.

## Boundaries
- This concept is editorial and explanatory only.
- This concept does not define software module order, runtime order, or realization pipelines.
- This concept does not redefine Governance statuses or Decision Record authority.
- This concept does not authorize promotion of unresolved Research claims.
