# Prioritized App implementation roadmap

These are outcome packages, not authorization to modify the App.

## 1. UI foundation: semantic selection, focus, and state language

Outcome: one typed workspace selection; separate hover/preview/tool-local state;
common commands; immediate state vocabulary; selection persistence tests.

Done: map, Cockpit, CurvatureBand, Editors, Objects, and import all acknowledge
one selection without event loops; language/layout changes preserve it.

## 2. One-plane shell, Home, and local-first mainView

Outcome: calm empty Home; complete local engineering plane; explicit view/
realization labels; geographic context attachment; Back/Home recovery.

Done: no-data, local-only, geographic, and mixed-realization acceptance
scenarios pass; MapLibre remains an adapter.

## 3. Contextual Cockpit and Objects separation

Outcome: the eight Cockpit states; at most three next actions and one notice;
object browsing moved to Objects; progressive evidence links.

Done: default Cockpit contains no property dump/object tree and remains useful
wide and narrow.

## 4. CurvatureBand constructive interaction

Outcome: synchronized intrinsic cursor/range, genuine degrees-of-freedom
handles, exact edit fallback, atomic command/undo, neighbor constraints.

Done: Scenario A passes with truthful locked/dependent values.

## 5. Alignment Editor simplification

Outcome: exact sequence/parameter editing as a focused working copy, sharing
selection and command semantics with CurvatureBand.

Done: switching representations does not change target or lose unsaved state.

## 6. TransEd as a live specialist

Outcome: catalogue-local selection, κ/κ′/κ″ live visualization, bounded `w1,w2`,
compare and explicit transfer to a declared working target.

Done: catalogue browsing never changes SPOT selection; transfer is previewable
and undoable.

## 7. Import evidence experience

Outcome: source/interpreted/unresolved/rejected/admitted states, evidence tree,
raw disclosure, preview, and explicit transfer boundary.

Done: Scenario B preserves exact and rejected evidence after transfer/edit.

## 8. AXTRAN candidate review

Outcome: problem declaration, comparable candidates, residuals, applicability,
ghost preview, explicit apply/reject, authority warning.

Done: Scenario C demonstrates that calculate, applicable, apply, and decision
are not collapsed.

## 9. Derived-application framework and platform demonstrator

Outcome: generic dependent-object placement/change-impact grammar, tested with
the platform example without implementing standards.

Done: Scenario D retains governing dependency and explains update/invalidation.

## 10. Comparative/realization depth and optional 3D

Outcome: target/realized/observed comparison, synchronized profile/plan/bands,
and task-scoped 3D.

Done: context, uncertainty, and scale/exaggeration are explicit; 3D is never a
required route for ordinary constructive work.

Packages 1–3 are prerequisites for consistent product behavior. Packages 4–9
can then proceed in two coordinated lanes (constructive tools and
evidence/application tools) so long as both consume the same foundation.
